# NEXORA AI — خارطة الطريق التنفيذية

> هذه الخارطة تصف حالة الكود الفعلية، لا مجرد أسماء الأزرار. لا تُعلَّم أي ميزة بأنها مكتملة إلا بعد اختبارها من الواجهة حتى الخدمة الخارجية، مع تسجيل نتيجة الاختبار.

## سياسة قبول الميزات
- كل زر يجب أن ينفذ إجراءً حقيقياً، أو يكون معطلاً مع توضيح السبب.
- كل طلب خارجي يعرض حالة نجاح/فشل مفهومة، ولا يعرض نجاحاً وهمياً.
- لا تُعتبر ملفات المشروع مولّدةً مشروعاً قابلاً للتشغيل قبل نجاح البناء داخل بيئة معزولة.
- لا تُعتبر جدولة المهمة تنفيذاً مستقلاً قبل تشغيلها فعلياً وتسجيل نتيجتها.
- لا دمج أو نشر تلقائي لتغييرات مولدة دون مراجعة واختبارات.

## ترتيب التنفيذ القادم (بوابات قبول إلزامية)

1. **اختبار الموثوقية:** اختبار chat وagents والبحث من واجهة منشورة ببيانات دخول صحيحة ومهام متعددة؛ إصلاح timeout الأولي دخل الإنتاج لكن لم يُثبت بعد باختبار وظيفي كامل.
2. **إكمال الأساس:** اختبارات Playwright/API، معالجة حالات 401/429/5xx والتحميل، وتوضيح حالة كل خدمة.
3. **ذاكرة ومحادثات:** تخزين آمن للمحادثات والذاكرة مع أدوات عرض/تعديل/حذف للمستخدم.
4. **وكيل تنفيذي حقيقي:** طابور خلفي، أدوات محددة، موافقات، سجل تدقيق، وعزل لكل مهمة.
5. **استوديو التطبيقات:** معاينة، اختبارات، إصلاحات تكرارية، ثم نشر منفصل بعد موافقة.
6. **الملفات والوسائط والصوت:** إضافة PDF/Office واختبار تدفقات الصور والفيديو والصوت على الهاتف.
7. **الأتمتة وAndroid:** جدولة دقيقة وتنبيهات ومزامنة دون اتصال، ثم تطبيق Android أصلي إذا لزم.
8. **الإطلاق:** مراجعة أمنية، اختبارات قبول كاملة، سياسة خصوصية وشروط استخدام، ثم فتح الخدمة للمستخدمين.

## ما لا نعلنه مكتملاً الآن
NEXORA ليست بعد منافساً مكتملاً لـ Manus. الموجود أساس قابل للتطوير وبعض أدوات أولية تعمل عند توفر إعداداتها. لا نعلن اكتمال الذاكرة طويلة الأجل، أو تنفيذ الوكيل المستقل، أو تطبيق Android أصلي، أو تشغيل فوري للمهام، أو اختبار كل الخدمات قبل اجتياز بوابات القبول أعلاه. بعض إجراءات الواجهة الآن موصولة فعلياً بنقاط API، لكن نجاحها التشغيلي يعتمد على إعداد مفاتيح الخدمات وحساباتها وإجراء اختبار مصادق عليه.
